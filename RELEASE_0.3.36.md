# 0.3.36 — роль «зрение»: кэш кандидатов, variant_set, узел выбора кандидата

- «3DA · постановка: кандидаты» (`3DAPlaceCandidates`, 3DA/auto):
  - дисковый кэш кандидатов: ключ — хэш всех входов без `pick` (плюс отпечаток файлов локации и кода, как у
    3DAPlacePose). Повторный вызов с тем же входом и другим `pick` берёт выбранного кандидата из кэша без пересчёта.
    Папка `<farm_root>/cand_cache` (или `THREEDA_CAND_CACHE`), последние `candidates.cache.keep` записей.
    В `candidates_json` новые поля `cache` (`hit|miss|off`), `computed_seconds`, `variant_set`;
  - новый необязательный вход `variant_set` (по умолчанию 0 — как раньше): 1 — те же места с другими разворотами,
    2 — соседние опоры (не вошедшие в набор 0, включая запасные) и соседние места. Выходы не менялись.
- Новый узел «3DA · выбор кандидата (зрение)» (`3DAVisionPick`, 3DA/auto): ответ модели
  `{"best", "reason", "problems"}` + `candidates_json` → `pick` (битый ответ или номер вне списка → −1 = лучший по
  оценке), `all_bad`, `note`. Координаты и сдвиги из ответа модели не читаются. Никогда не падает.
- Числа — `config/placement.yaml`, раздел `candidates`: `cache`, `variant_sets`, `vision` (не больше 3 прогонов).

Что не изменилось для manual: 3DALocation, 3DAPlacePose, 3DAControl и остальные узлы художников — входы, выходы,
поведение и `IS_CHANGED` те же. В отпечаток 3DAPlacePose, как и при каждом релизе, входят `nodes.py`,
`posev2/*.py` и `placement.yaml`, поэтому после установки первый прогон 3DAPlacePose пересчитает постановку
(результат тот же).
